# Constraints: Operations

Durable MUST/MUST NOT rules for how the owner runs the backend, its environments, knowledge releases, and monitoring. Part of the index in [`CONSTRAINTS.md`](../../CONSTRAINTS.md); paths in backticks are relative to the repository root.

Owner decision (2026-11-01): the owner runs every environment alone and is not fluent in the terminal, Python, containers, or server tooling, so operating the service must not require that knowledge. These rules apply to any feature that adds or changes how the service, an environment (local, QA, prod), a knowledge release, or monitoring is set up, started, stopped, checked, updated, backed up, restored, or rolled back. They add to [`hosting-and-pilot.md`](hosting-and-pilot.md); they never relax a safety, privacy, or pilot gate, except the owner-decided QA test-data-only exception in [`hosting-and-pilot.md`](hosting-and-pilot.md).

## Owner operability

- **MUST**: every routine operation (first setup, start, stop, status, update, logs, backup, restore, rollback) is one named command run from the repository root (`./scripts/init.sh --<operation>` or a sibling script in `scripts/`), with no virtualenv activation, `cd`, exported variable, or Python module path typed by the owner.
- **MUST**: a command checks its prerequisites before changing anything; when one is missing it stops and names, in plain words, what is missing and the single command or step that fixes it. Raw tracebacks go to a log file whose path is printed, never as the only output.
- **MUST**: every command ends with one plain-language result line (what worked, or what failed and the next step) and exits non-zero on failure; re-running a completed setup or start reports the current state instead of failing or duplicating work.
- **MUST**: per-environment settings live in one commented settings file created by the setup command with safe defaults; secrets and tokens are generated by a command, never typed by hand, and the owner never edits source code, JSON, or YAML to operate the service.
- **MUST**: a destructive or hard-to-reverse operation (restore, rollback, delete, publishing to QA or prod) states what will change, asks for confirmation, and names its tested way back before it runs.
- **MUST**: each operation is documented in the owner guide (`docs/owner-guide.md`, created by the first feature that needs it) as numbered copy-paste steps with the expected result and what to do if it differs; internals stay in `backend/README.md`.
- **MUST**: a feature that changes an existing operator CLI (for example `pilot_ops.py`, `knowledge_release.py`, `knowledge_review.py`, `run_source_updates.py`) also exposes that operation through a named command above.
- **MUST**: acceptance includes a walkthrough that runs every documented operation exactly as the owner guide writes it, from a fresh checkout, including at least one missing-prerequisite case and one recovery.
- **MUST**: a setup command downloads only artifacts named by a reviewed pin, from the pin's own upstream location, and verifies each one against the pin before use; it **MUST NOT** edit a pin to make a mismatch pass, and the answer service itself never downloads. Reason: [`local_rag_bootstrap`](../specs/local_rag_bootstrap.md).
- **MUST**: a local start command binds only loopback (`127.0.0.1`), runs the service without reload in the default profile, passes only an allowlisted environment (no inherited `MANIJERO_*`), and starts only when the status check it mirrors is all `OK`; it is not a pilot launcher. Reason: [`local_full_rag_stack`](../specs/local_full_rag_stack.md).
- **MUST**: a container command publishes only on host `127.0.0.1`, runs the default profile without reload as a non-root user, passes only the campaign from the host, acts (stop, remove) only on containers carrying the `org.manijero.managed=1` label, and builds only from pin-verified local artifacts with a digest-pinned base image and no model download; it is not a pilot launcher. Reason: [`backend_container_image`](../specs/backend_container_image.md).
- **MUST**: a smoke or check command that drives the apps is read-only for the owner's data: it opens no land store, never saves or clears a saved address, and never uninstalls an app (so no `connectedAndroidTest`). It reports only outcome codes, source counts, and addresses, never question, answer, or passage text. A check against QA (`--qa-check`) sends only the fixed synthetic question and at most one `useful` rating per run, never retried. Reason: [`local_end_to_end_smoke`](../specs/local_end_to_end_smoke.md), [`qa_real_device_check`](../specs/qa_real_device_check.md).
- **MUST**: a measurement command is read-only over loopback, takes no arguments from the owner, prints only aggregate counts and timings (never question, answer, passage, land, or token text), and its numbers are host-specific evidence that **MUST NOT** be described as pilot capacity, a service promise, or a pass/fail result. Reason: [`local_load_test`](../specs/local_load_test.md).
- **MUST**: a rehearsal or check command that drives the service is read-only for `knowledge/` and owner data, writes only inside one temporary workspace it removes, sends `land_context.mode = "general"` with no lands and no retention, declares any synthetic content in its output, and reports only fixed step labels, reason codes, counts, and the service address — never question, answer, passage, land, or token text. Reason: [`rag_demo_rehearsal`](../specs/rag_demo_rehearsal.md).
- **MUST**: a results-recording command stores only anonymous `P<n>` codes, fixed outcome codes, minutes, and screened notes outside the checkout with mode `0600`, refuses personal-data-looking input without echoing it, and asks before replacing a record. Reason: [`usability_session`](../specs/usability_session.md).
- **MUST**: every environment settings file names `MANIJERO_ENVIRONMENT` and `MANIJERO_DEPLOYMENT_PROFILE` explicitly, and a non-local file without `pilot` is refused, never defaulted to local or `development`; an environment's access keys are generated by a command into that environment's own home outside the checkout, mode `0600`, never printed or committed; prod has no settings, home, or command until it is planned. Reason: [`environment_profiles`](../specs/environment_profiles.md).
- **MUST**: the QA commands (`--qa-deploy`, `--qa-update`, `--qa-rollback`, `--qa-status`, `--qa-stop`) publish the container `manijero-qa` only on host `127.0.0.1`, act only on containers carrying both the `org.manijero.managed=1` and `org.manijero.environment=qa` labels, touch Tailscale Funnel only for their own HTTPS 443 entry pointing at the QA port (a different entry is a prerequisite problem, never changed), turn Funnel off before stopping the container, check every prerequisite and ask for `yes` before deploy, update, or rollback, and restore the earlier version when an update or rollback fails. Account setup (Tailscale login, HTTPS, Funnel) is never automated. Reason: [`qa_server_deployment`](../specs/qa_server_deployment.md).
- **MUST NOT**: commit a real QA host or any credential; `--qa-deploy` writes the QA address only into the git-ignored `qa-address.local` and the QA settings file outside the checkout (`MANIJERO_PUBLIC_URL`). Reason: [`client_environment_builds`](../specs/client_environment_builds.md), decision 3; [`qa_server_deployment`](../specs/qa_server_deployment.md).

## Monitoring

- **MUST**: monitoring is free, self-hosted, and needs no separate install beyond Docker Desktop, account, query language, or hand-built panel. Owner decision (2026-11-02): it has its own start, status, and stop commands (`./scripts/init.sh --monitoring-start|--monitoring-status|--monitoring-stop`) instead of starting with the service it watches; the service commands keep working without Docker. Reason: [`monitoring_dashboard`](../specs/monitoring_dashboard.md).
- **MUST**: monitoring containers publish only on host `127.0.0.1` and only the dashboard, use digest-pinned images (an explicit version tag until the digest is read), act only on containers carrying `org.manijero.managed=1`, keep only `manijero_*` and `up` series with the `backend_health_metrics` label allowlist plus `env`, `job`, `instance`, and run Grafana with anonymous Viewer only (no login form, Explore, editing, plugin downloads, analytics, or update checks). Reason: [`monitoring_dashboard`](../specs/monitoring_dashboard.md).
- **MUST**: a down or unreachable QA host is still detected by a check that runs outside that host; monitoring that lives only on the host MUST NOT be described as outage alerting. Owner decision (2026-11-07): the QA alerts run on the same Mac as QA, so they detect service problems only while it is awake and MUST NOT be described as host-outage alerting. Reason: [`qa_service_alerts`](../specs/qa_service_alerts.md).
- **MUST**: QA alerts keep the Telegram bot token and chat id only in `~/manijero/alerts/credentials/telegram.json` (directory `0700`, file `0600`), never in argv, output, logs, state, the launchd file, or exception text; send only fixed message texts (problem kind, first step, times, and the error share, never the `ts.net` address, question, answer, land, name, or client text); call `launchctl` only for the label `org.manijero.qa-alerts`; confirm a problem on 2 checks in a row, remind at most every 4 hours, and send the same problem kind at most once per 60 minutes. Reason: [`qa_service_alerts`](../specs/qa_service_alerts.md).
- **MUST**: the dashboard opens in a web browser at an address printed by the status command and shows each critical check as a plain-language OK / warning / problem status with what it means and the first thing to do, not only raw numbers or charts.
- **MUST**: `GET /metrics` carries only fixed-label counts, timings, and the 16-hex knowledge release id; it is open only in the `development` profile and needs a valid client token in `pilot`. Reason: [`backend_health_metrics`](../specs/backend_health_metrics.md).
- **MUST NOT**: show or store question text, land context, names, notes, client identifiers, or tokens in metrics, dashboard, or alerts; the pilot logging rule in [`hosting-and-pilot.md`](hosting-and-pilot.md) applies unchanged.
- **MUST**: an alert reaches the owner on a channel the owner chose and already uses, says what is wrong in plain words and the first step, and never fires for the same unresolved problem more than once per hour.
