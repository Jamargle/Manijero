### Existing patterns to follow

- Operator modules: fixed English sentences, injected ports, exit `0`/`1`/`2`, tracebacks only in a printed log path.
- Settings: allowlisted `KEY=VALUE`, never sourced, line-numbered errors, created with `O_EXCL`, never overwritten.
- Secrets: digest-only clients file via `pilot_ops.upsert_client`; files `0600`; nothing secret in output.

### Planner decisions (the owner may rename before implementation)

- Commands `--environments-status` (read-only, all three) and `--qa-settings-setup` (avoids colliding with `qa_server_deployment`'s future deploy commands).
- Homes `~/manijero/local` (existing) and `~/manijero/qa`; credentials and releases live in the home, outside the checkout, so they can never be committed; `.gitignore` guard patterns cover accidental copies.
- `MANIJERO_ENVIRONMENT` (`local`/`qa`) names the environment; `MANIJERO_DEPLOYMENT_PROFILE` (`development`/`pilot`) names the service profile; both required in every file read by `read_profile_settings`.
- Local credentials (orchestrator answer 1): client `local-test-device`, made by `--local-rag-setup`, never overwriting an existing token; the local service does not read them. Old local files without the two lines keep working and are fixed by `--local-rag-setup` (keeps the owner's working setup working, decision 1).
- Local launch env unchanged (orchestrator answer 2): unset profile is `development`, i.e. local; no dependency on `answer_pipeline_trace`.
- QA placeholder host `https://qa.manijero.invalid` (RFC 2606 reserved TLD, never resolves).
- One QA test client `qa-test-device`, 20 requests/minute (the runbook's default); its plaintext token is kept `0600` in the QA home for `client_environment_builds`.

### Current gaps

- No pilot-profile service can run anywhere yet (privacy review `pending`); a live authenticated answer stays unobserved.
- Local credentials are unused until `client_environment_builds` wires them into test builds.
